# Сервис по получению метеорологических данных

Консольное Java-приложение, которое получает данные о погоде из **Яндекс Погоды API** (`https://api.weather.yandex.ru/v2/forecast`), выводит полный JSON-ответ, текущую температуру и среднюю температуру по прогнозу за заданное количество суток.

---

## Возможности

- GET-запрос к Яндекс Погоде с координатами (`lat`, `lon`) и параметром `limit` (число суток прогноза).
- Передача ключа доступа в заголовке `X-Yandex-Weather-Key`.
- Вывод **полного JSON-ответа «как есть»** в консоль.
- Извлечение и вывод **текущей температуры** `fact.temp`.
- Расчёт **средней температуры** по первым `limit` суткам из `forecasts[*].parts.day.temp_avg` (среднее арифметическое).
- Устойчивый разбор ответа через Jackson-модели (`record`), защита от отсутствующих полей.

---

## Требования

- **JDK 17+** 
- **Maven 3.8+**
- Доступ в интернет
- API-ключ Яндекс Погоды уже вписан в `src/main/java/weather/WeatherApp.java`

---

## Как запустить

### Шаг 1. Клонировать репозиторий

```bash
git clone <repo-url> hw-api-weather
cd hw-api-weather
```

### Шаг 2. Собрать и запустить

```bash
mvn compile exec:java
```

**Ожидаемый вывод:**
```
Ответ сервиса как есть:
{"now":...,"fact":{"temp":0,...},"forecasts":[...]}

Текущая температура (fact.temp): 0
Значения temp_avg за 7 суток: [2, 2, 3, 1, 1, 4, 4]
Средняя температура за 7 суток: 2,43 °C
```

## Примечание по безопасности

В данном проекте API-ключ сохранил прямо в исходном коде (`WeatherApp.java`), чтобы запуск был максимально простым — клонировал и запустил.
В реальном проекте так делать нельзя: ключ попадёт в историю git и станет доступен всем. Правильные способы:
- переменная окружения (`System.getenv("YANDEX_WEATHER_KEY")`)
- конфигурационный файл вне репозитория (`.env`, `application.properties` в `.gitignore`)
